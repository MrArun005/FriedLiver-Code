# FriedLiver fork: memory plan

Why: Antigravity, itself a VS Code fork, ate the user's RAM. Measured here:
VS Code at 761 MB against 314 MB for the FriedLiver Electron app (0.x, since retired). This plan
lists what a Code - OSS fork can cut. Items 3, 6, 7 and 10–12 were measured
with `scripts/stress-demo.mjs` (idle and 15 agents); their outcome is in the
last column and the numbers in [benchmarks.md](benchmarks.md#cutting-memory-at-the-app-level).

Evidence links point at upstream tag `1.142.0`:
`https://github.com/microsoft/vscode/blob/1.142.0/<path>#L<line>`.

## Ranked changes

| 2 | **Keep the agent host process from starting.** | [`src/vs/code/electron-main/app.ts#L760-L769`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/code/electron-main/app.ts#L760-L769): a utility process spawned on the first window request when AI features are enabled. | 3 | **Drop the `github` built-in.** Keep `git` and `git-base`. | [`extensions/github/package.json#L16`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/github/package.json#L16) activates on `*`, as do [`git#L51`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/git/package.json#L51) and [`git-base#L14`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/git-base/package.json#L14) | One fewer eagerly loaded extension, including octokit | Low to medium: loses Publish to GitHub and permalinks | **Measured, kept** (2026-10-16): switched off, the extension host held 1.1 MB less heap after GC and the same PSS. | 4 | **Exclude `node_modules` from the file watcher.** | The watcher is a utility process ([`watcherMain.ts`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/files/node/watcher/watcherMain.ts)). Excludes are handed to @parcel/watcher natively ([`parcelWatcher.ts#L381`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/files/node/watcher/parcel/parcelWatcher.ts#L381)), so excluded trees are never watched. The upstream default only excludes `.git/objects` and similar ([`files.contribution.ts#L294-L307`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/files/browser/files.contribution.ts#L294-L307)) | Lower watcher memory and CPU on JavaScript repos | Low: the Explorer won't auto-refresh inside node_modules | **Done**: theme extension `files.watcherExclude` |
| 5 | **Turn off TypeScript type acquisition** and consider a single tsserver. | ATA off passes `--disableAutomaticTypingAcquisition`, so tsserver doesn't fork its typings installer ([`spawner.ts#L210-L212`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L210-L212)). `useSyntaxServer: "auto"` runs a second, partial-semantic tsserver ([`spawner.ts#L108-L120`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L108-L120), [`#L200-L206`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L200-L206)). `maxTsServerMemory` (default 3072, [`package.json#L2559`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/package.json#L2559)) is only a cap | ATA off: one Node process fewer, and no npm downloads. Syntax server `never`: one more process fewer | ATA: low (JavaScript projects lose auto-downloaded `@types`). Syntax server: medium (slower early IntelliSense) | **Done**: `typescript.disableAutomaticTypeAcquisition`. `useSyntaxServer` is **listed only** |
| 6 | **Trim the marketplace built-ins.** | product.json `builtInExtensions`: `ms-vscode.js-debug`, `ms-vscode.js-debug-companion`, `ms-vscode.vscode-js-profile-table` ([`product.json`](https://github.com/microsoft/vscode/blob/1.142.0/product.json)) | Smaller install and fewer activations. Drop the companion (used for remote browser debugging) and the profile table | Medium if js-debug is dropped too. Keep js-debug | **Measured, kept**: neither activates at startup (they wait for a command, or for a `.cpuprofile`), so dropping them saves 2.5 MB of disk and no memory. They would cost remote browser debugging and the profile table view |
| 7 | **Leave small eager built-ins alone unless measurement shows otherwise.** | `merge-conflict` ([`package.json#L22`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/merge-conflict/package.json#L22)) and `debug-auto-launch` ([`#L18`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/debug-auto-launch/package.json#L18)) activate on `onStartupFinished`. `npm` activates on `workspaceContains:package.json` ([`#L47`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/npm/package.json#L47)) and scans for scripts unless `npm.autoDetect` is `off` | A few MB each | Low to medium: `npm.autoDetect: off` hides npm scripts in Run Task. **Not set** | **Measured, kept**: `merge-conflict` and `debug-auto-launch` off, with the two in item 6, saved 0.9 MB of extension-host heap and no PSS. `npm` itself is cheap; what it cost was the JSON server it started (item 11), now fixed without `npm.autoDetect: off` |
| 8 | **Pty host and terminal rendering.** | The pty host starts on the first window connection request ([`ptyHostService.ts#L52-L56`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/terminal/node/ptyHostService.ts#L52-L56), [`#L111-L114`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/terminal/node/ptyHostService.ts#L111-L114)). | 10 | **Test Chromium and V8 flags one at a time.** | What upstream already sets ([`mainImpl.ts#L360-L395`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L360-L395)): `enable-features` (NetAdapterMaxBufSize, EarlyEstablishGpuChannel, EstablishGpuChannelAsync), `disable-features` (CalculateNativeWinOcclusion, HideCursorWhileTyping), `disable-blink-features` (FontMatchingCTMigration, StandardizedBrowserZoom), `max-active-webgl-contexts=32`. `js-flags` come from argv.json ([`#L575-L592`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L575-L592)), with an allowlist of switches ([`#L252-L268`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L252-L268)). Candidates to try: `--js-flags=--optimize-for-size`, and `disable-features=SpareRendererForSitePerProcess` (Chromium keeps a spare renderer process warm). Docs: [Electron command-line switches](https://www.electronjs.org/docs/latest/api/command-line-switches), [Chromium flags in VS Code (argv.json)](https://code.visualstudio.com/docs/configure/command-line) | Uncertain; renderer and GPU process sizes | Medium: speed regressions. Never ship `disable-hardware-acceleration` as a default | `--js-flags=--optimize-for-size`: **tried, not set**. With 15 agents the app held 80 MB less on average and once settled, and its peak fell from about 1070 to 740 MB; at rest it saved about 60 MB in the first minute and nothing after. But the window took 8 % longer to show and the Agents view 12 % longer (slower in 6 of 6 alternating launches), the workbench used 3 points more CPU under load, and, because upstream hands the flag to utility processes in `execArgv` (`utilityProcess.ts:250`), an extension's `child_process.fork()` without its own `execArgv` then fails with "bad option: --js-flags" (the same happens upstream to anyone who sets `js-flags` in argv.json). `--max-semi-space-size=2` alone: no clear change. `disable-features=SpareRendererForSitePerProcess`: **tried, not set**, no change: this app never keeps a spare renderer (the process list has none to begin with) |
| 11 | **Don't start the JSON language server until JSON is open.** | It started about 5 s after every window opened a folder with a `package.json`, with no JSON file open: the debug adapter manager collects task labels for launch.json's schema ([`debugAdapterManager.ts#L96-L110`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts#L96-L110)), which asks every task provider for its tasks; npm's opens `package.json` as a text document ([`extensions/npm/src/tasks.ts#L491`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/npm/src/tasks.ts#L491)), and that fires `onLanguage:json` for `json-language-features`, `configuration-editing` and `extension-editing` | 25–34 MB at rest: the JSON server process, plus about 1 MB of extension-host heap | None seen: the labels are collected when the first JSON or JSONC editor opens, which starts the JSON server anyway, and the schema updates in place | **Done**: patch `0050-json-server-only-for-json.patch` |
| 12 | **No tools server process per chat for agents that take MCP over HTTP.** | ACP's `agentCapabilities.mcpCapabilities.http`; Claude's adapter (`claude-agent-acp` 0.23 and 0.93) and Gemini CLI (0.64) say `http: true, sse: true`, `codex-acp` (2.2) `http: true` and map an HTTP server's headers to `http_headers` | About 19 MB per chat: 285 MB with 15 chats | Medium (new transport): kept to the same tools, checks, token and caps; agents that don't advertise HTTP still get `dist/bridge.js` | **Done**: `src/bridge/http.ts`, SECURITY.md "The HTTP endpoint" |

Also done in the theme extension, for design and for a little memory:
`editor.minimap.enabled: false` (one canvas fewer per editor) and
`extensions.ignoreRecommendations: true` (no recommendation lookups or
toasts).

## Summary of where each change lives

- **Theme extension `configurationDefaults` (done):** `files.watcherExclude`
  (`**/node_modules/*/**`), `typescript.disableAutomaticTypeAcquisition`,
  `editor.minimap.enabled`, `extensions.ignoreRecommendations`.
- **Build and prepare step (build owner):** drop `extensions/copilot` and the
  `@github/copilot-sdk` runtime packaging (done). `extensions/github` and the
  `builtInExtensions` trim were measured and kept (items 3 and 6).
- **Patch (done):** `0050` keeps the JSON language server from starting
  until JSON is open (item 11). The V8 flag in item 10 was measured and not
  set.
- **Agents extension (done):** the FriedLiver tools over HTTP for agents that
  take it (item 12).
- **product.json (build owner):** no `defaultChatAgent`, `tasConfig`,
  `updateUrl` or `aiConfig`; `extensionsGallery` pointing at Open VSX, or
  none.
- **Measure before deciding:** `typescript.tsserver.useSyntaxServer: never`,
  `terminal.integrated.gpuAcceleration`,
  `terminal.integrated.enablePersistentSessions` and `chat.disableAIFeatures`.
  `npm.autoDetect: off` is no longer needed (item 11).

The measurements behind items 3, 6, 7, 10, 11 and 12 are in
[benchmarks.md, "Cutting memory at the app level"](benchmarks.md#cutting-memory-at-the-app-level).
