# FriedLiver fork: memory plan

Why: Antigravity, itself a VS Code fork, ate the user's RAM. Measured here:
VS Code at 761 MB against 314 MB for the FriedLiver Electron app. This plan
lists what a Code - OSS fork can cut. It contains no measurements. The build
agent measures each item, for example with Help > Open Process Explorer and
the `bench:ram` harness.

Evidence links point at upstream tag `1.142.0`:
`https://github.com/microsoft/vscode/blob/1.142.0/<path>#L<line>`.

## Ranked changes

| # | Change | Evidence | Expected effect | Risk | Where |
|---|---|---|---|---|---|
| 1 | **Don't ship the built-in `copilot` extension (Copilot Chat), and leave `defaultChatAgent` out of product.json.** | [`extensions/copilot/package.json#L80`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/copilot/package.json#L80) activates on `onStartupFinished`, in every window. The source tree is 62 MB. The build packages it separately from the other built-ins ([`build/lib/extensions.ts#L318-L326`](https://github.com/microsoft/vscode/blob/1.142.0/build/lib/extensions.ts#L318-L326), [`build/gulpfile.extensions.ts#L290-L293`](https://github.com/microsoft/vscode/blob/1.142.0/build/gulpfile.extensions.ts#L290-L293)) and bundles the `@github/copilot-sdk` runtime into the app ([`build/gulpfile.vscode.ts#L48-L50`](https://github.com/microsoft/vscode/blob/1.142.0/build/gulpfile.vscode.ts#L48-L50), [`#L248`](https://github.com/microsoft/vscode/blob/1.142.0/build/gulpfile.vscode.ts#L248)) | Largest single cut to extension-host heap and to install size | Low: FriedLiver brings its own agents | Build (prepare step) |
| 2 | **Keep the agent host process from starting.** | [`src/vs/code/electron-main/app.ts#L760-L769`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/code/electron-main/app.ts#L760-L769): a utility process spawned on the first window request when AI features are enabled. With item 1 it should never start; check the process list. `chat.disableAIFeatures` (window scope, [`chat.shared.contribution.ts#L2423`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts#L2423)) would guarantee it but also hides the built-in chat UI | One whole Node process fewer | Medium: only set the setting if `friedliver-agents` doesn't use the chat UI. **Not set** | Lead decision |
| 3 | **Drop the `github` built-in.** Keep `git` and `git-base`. | [`extensions/github/package.json#L16`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/github/package.json#L16) activates on `*`, as do [`git#L51`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/git/package.json#L51) and [`git-base#L14`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/git-base/package.json#L14) | One fewer eagerly loaded extension, including octokit | Low to medium: loses Publish to GitHub and permalinks | Build (exclude in prepare) |
| 4 | **Exclude `node_modules` from the file watcher.** | The watcher is a utility process ([`watcherMain.ts`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/files/node/watcher/watcherMain.ts)). Excludes are handed to @parcel/watcher natively ([`parcelWatcher.ts#L381`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/files/node/watcher/parcel/parcelWatcher.ts#L381)), so excluded trees are never watched. The upstream default only excludes `.git/objects` and similar ([`files.contribution.ts#L294-L307`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/files/browser/files.contribution.ts#L294-L307)) | Lower watcher memory and CPU on JavaScript repos | Low: the Explorer won't auto-refresh inside node_modules | **Done**: theme extension `files.watcherExclude` |
| 5 | **Turn off TypeScript type acquisition** and consider a single tsserver. | ATA off passes `--disableAutomaticTypingAcquisition`, so tsserver doesn't fork its typings installer ([`spawner.ts#L210-L212`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L210-L212)). `useSyntaxServer: "auto"` runs a second, partial-semantic tsserver ([`spawner.ts#L108-L120`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L108-L120), [`#L200-L206`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/src/tsServer/spawner.ts#L200-L206)). `maxTsServerMemory` (default 3072, [`package.json#L2559`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/typescript-language-features/package.json#L2559)) is only a cap | ATA off: one Node process fewer, and no npm downloads. Syntax server `never`: one more process fewer | ATA: low (JavaScript projects lose auto-downloaded `@types`). Syntax server: medium (slower early IntelliSense) | **Done**: `typescript.disableAutomaticTypeAcquisition`. `useSyntaxServer` is **listed only** |
| 6 | **Trim the marketplace built-ins.** | product.json `builtInExtensions`: `ms-vscode.js-debug`, `ms-vscode.js-debug-companion`, `ms-vscode.vscode-js-profile-table` ([`product.json`](https://github.com/microsoft/vscode/blob/1.142.0/product.json)) | Smaller install and fewer activations. Drop the companion (used for remote browser debugging) and the profile table | Medium if js-debug is dropped too. Keep js-debug | product.json (build owner) |
| 7 | **Leave small eager built-ins alone unless measurement shows otherwise.** | `merge-conflict` ([`package.json#L22`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/merge-conflict/package.json#L22)) and `debug-auto-launch` ([`#L18`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/debug-auto-launch/package.json#L18)) activate on `onStartupFinished`. `npm` activates on `workspaceContains:package.json` ([`#L47`](https://github.com/microsoft/vscode/blob/1.142.0/extensions/npm/package.json#L47)) and scans for scripts unless `npm.autoDetect` is `off` | A few MB each | Low to medium: `npm.autoDetect: off` hides npm scripts in Run Task. **Not set** | Measure first |
| 8 | **Pty host and terminal rendering.** | The pty host starts on the first window connection request ([`ptyHostService.ts#L52-L56`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/terminal/node/ptyHostService.ts#L52-L56), [`#L111-L114`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/terminal/node/ptyHostService.ts#L111-L114)). Persistent sessions are on by default and make the window connect at startup ([`terminalConfiguration.ts#L555`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts#L555)). `gpuAcceleration` `auto` gives each terminal a WebGL context ([`#L345`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts#L345); upstream raises the context limit to 32, [`mainImpl.ts#L393-L395`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L393-L395)) | Uncertain: FriedLiver is terminal-heavy, so the pty host will run anyway. `gpuAcceleration: off` trades GPU memory for slower rendering | Medium. **Not set** | Measure |
| 9 | **Keep shared-process services idle through product.json.** | The shared process ([`sharedProcess.ts`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/sharedProcess/electron-main/sharedProcess.ts), [`sharedProcessMain.ts`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/code/electron-utility/sharedProcess/sharedProcessMain.ts)) hosts extension management, the gallery, telemetry, sync and tunnels. The relevant settings are application-scoped, so the product has to handle them: leave out `tasConfig` (experiments, [`assignmentService.ts#L618`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/workbench/services/assignment/common/assignmentService.ts#L618)), `updateUrl` ([`update.config.contribution.ts#L19`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/update/common/update.config.contribution.ts#L19)) and `aiConfig` (telemetry, [`telemetryService.ts#L321`](https://github.com/microsoft/vscode/blob/1.142.0/src/vs/platform/telemetry/common/telemetryService.ts#L321)). See DEFAULTS.md | Small memory saving; no polling or experiment fetches | None. Point `extensionsGallery` at Open VSX if extensions are wanted | product.json (build owner) |
| 10 | **Test Chromium and V8 flags one at a time.** | What upstream already sets ([`mainImpl.ts#L360-L395`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L360-L395)): `enable-features` (NetAdapterMaxBufSize, EarlyEstablishGpuChannel, EstablishGpuChannelAsync), `disable-features` (CalculateNativeWinOcclusion, HideCursorWhileTyping), `disable-blink-features` (FontMatchingCTMigration, StandardizedBrowserZoom), `max-active-webgl-contexts=32`. `js-flags` come from argv.json ([`#L575-L592`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L575-L592)), with an allowlist of switches ([`#L252-L268`](https://github.com/microsoft/vscode/blob/1.142.0/src/mainImpl.ts#L252-L268)). Docs: [Electron command-line switches](https://www.electronjs.org/docs/latest/api/command-line-switches), [Chromium flags in VS Code (argv.json)](https://code.visualstudio.com/docs/configure/command-line) | Uncertain; renderer and GPU process sizes | Medium: speed regressions. Never ship `disable-hardware-acceleration` as a default | Patch `src/mainImpl.ts` after measuring |

Also done in the theme extension, for design and for a little memory:
`editor.minimap.enabled: false` (one canvas fewer per editor) and
`extensions.ignoreRecommendations: true` (no recommendation lookups or
toasts).

## Summary of where each change lives

- **Theme extension `configurationDefaults` (done):** `files.watcherExclude`
  (`**/node_modules/*/**`), `typescript.disableAutomaticTypeAcquisition`,
  `editor.minimap.enabled`, `extensions.ignoreRecommendations`.
- **Build and prepare step (build owner):** drop `extensions/copilot` and the
  `@github/copilot-sdk` runtime packaging, drop `extensions/github`, and trim
  `builtInExtensions`.
- **product.json (build owner):** no `defaultChatAgent`, `tasConfig`,
  `updateUrl` or `aiConfig`; `extensionsGallery` pointing at Open VSX, or
  none.
- **Measure before deciding:** `typescript.tsserver.useSyntaxServer: never`,
  `npm.autoDetect: off`, `terminal.integrated.gpuAcceleration`,
  `terminal.integrated.enablePersistentSessions`, `chat.disableAIFeatures`,
  and the Chromium/V8 flags in item 10.

See also: [Activation events](https://code.visualstudio.com/api/references/activation-events)
and [VS Code performance issues wiki](https://github.com/microsoft/vscode/wiki/Performance-Issues).
